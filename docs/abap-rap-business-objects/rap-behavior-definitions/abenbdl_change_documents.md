# RAP - changedocuments

## Syntax

``` abap
... changedocuments master [asynchronous] 
                           [utc] 
                           ( ChangeDocumentObject ) 
  | changedocuments dependent [by _Assoc]  
```

### Addition

[1. `... asynchronous ...`](abenbdl_change_documents.md#addition-1)

[2. `... utc ...`](abenbdl_change_documents.md#addition-2)

## Prerequisite

- As a prerequisite for enabling RAP change documents, [BDEF strict mode](abenbdl_strict.md) must be switched on.

- A [RAP persistent table](../../abap-glossary/abenrap_persistent_table_glosry.md) must be specified using the syntax addition [`persistent table`](abenbdl_persistent_table.md).

## Overview

### Description

[RAP change documents](../../abap-glossary/abenrap_change_documents_glosry.md) are used to log changes of the [RAP persistent table](../../abap-glossary/abenrap_persistent_table_glosry.md) in a [change document object](../../abap-glossary/abenchange_document_obj_glosry.md) `ChangeDocumentObject`. A change document object is a [repository object](../../abap-glossary/abenrepository_object_glosry.md) that logs the changes made to specific database tables assigned to it. RAP change documents are defined in the [entity behavior characteristics](../../abap-glossary/abencds_entity_properties_glosry.md) for each [entity behavior definition](../../abap-glossary/abencds_entity_bdef_glosry.md) for which changes are logged, thereby defining the respective RAP BO entity as a [change documents-enabled RAP BO entity](../../abap-glossary/abenrap_change_doc_enabled_glosry.md). No implementation in the [ABAP behavior pool](../../abap-glossary/abenbehavior_pool_glosry.md) is required.

RAP BO entities can be specified either as [change documents master entity](../../abap-glossary/abenrap_change_doc_master_glosry.md) or as [change documents dependent entity](../../abap-glossary/abenrap_change_doc_dpndnt_glosry.md):

- A RAP change documents master entity has its own [change document object](../../abap-glossary/abenchange_document_obj_glosry.md) for logging changes to persisted data. It is the root of the subtree of entities for which change document data is recorded.

- A RAP change documents dependent entity uses the change document object that is defined in its change documents master entity to log changes to persisted data.

The following rules apply:

- The change documents master entity is defined using the syntax `changedocuments master (ChangeDocumentObject)`.

  - `ChangeDocumentObject` is the name of a [change document object](../../abap-glossary/abenchange_document_obj_glosry.md). It can be generated by a quick fix in [ABAP development tools for Eclipse](../../abap-glossary/abenadt_glosry.md).

    **Note:** Change document objects contain options for the generation of change documents. In RAP, these options are irrelevant, the only information that matters is the name of the change document object, which serves as a key field in the change documents results. There is dedicated BDEF syntax available to specify further options for RAP change documents. See the topic [RAP - `changedocuments, Options`](abenbdl_changedocs_options.md) for further details.

  - Any entity can be the change documents master entity. Typically, the [RAP BO root node](../../abap-glossary/abenrap_bo_root_entity_glosry.md) is used as the change documents master entity, but this is optional.

  - A change documents master entity can have zero to n change documents dependent entities.

  - A RAP BO can currently have no more than one change documents master entity.

- The change documents dependent entities are defined using the syntax `changedocuments dependent [by _Assoc]`

  - All [RAP BO entities](../../abap-glossary/abenrap_bo_entity_glosry.md) that are on a lower hierarchy level in the [CDS composition tree](../../abap-glossary/abencds_composition_tree_glosry.md) than the change documents master entity can be defined as dependent entities.

  - The addition `by _Assoc` is optional. It can be used to specify the association to the change documents master entity. When omitted, the [ancestor association](../../abap-glossary/abencds_ancestor_assoc_glosry.md) to the change documents master entity is used implicitly.

- All change documents-enabled entities must form a tree in the composition hierarchy of the RAP BO in question.

- Further options for RAP change documents are defined in the [entity behavior body](../../abap-glossary/abencds_entity_body_glosry.md) as described in the topic [RAP - `changedocuments, Options`](abenbdl_changedocs_options.md).

By default, changes to the persisted data of a RAP BO are logged on CDS entity level, and not on the level of the corresponding [persistent tables](../../abap-glossary/abenrap_persistent_table_glosry.md). This means that the metadata of the fields of the CDS entities are evaluated, for example, details about typing, reference annotations to a [currency key](../../abap-glossary/abencurrency_key_glosry.md) or [unit key](../../abap-glossary/abenunit_glosry.md), and the change document settings on field level defined in a [CDS simple type](../../abap-glossary/abencds_simple_type_glosry.md) or a [DDIC data element](../../abap-glossary/abendata_element_glosry.md).

## Availability

- [Managed RAP BO](../../abap-glossary/abenmanaged_rap_bo_glosry.md)

- In [BDEF extensions](../../abap-glossary/abenrap_extension_glosry.md), it is not allowed to define a change documents master entity. Defining change documents dependent entities is allowed in node extensions, as long as the change document enabled entities still form a tree after this usage.

- If persisted data is changed using a [projection BDEFs](../../abap-glossary/abencds_proj_bdef_glosry.md) or a [RAP BO interface](../../abap-glossary/abenrap_bo_interface_glosry.md), these changes are logged in the change document object of the [base BO](../../abap-glossary/abenrap_projected_bo_glosry.md) for change-documents-enabled RAP BO entities automatically. The change documents of the managed base BO are reused automatically, and no explicit enabling is required.

### Hint

In on-premise systems, change documents integration works in the language version [Standard ABAP](../../abap-glossary/abenstandard_abap_glosry.md) only.

### Example

**Caution**

The programs and program extracts presented in the ABAP Keyword Documentation are only syntax examples and are not intended for direct use in a production system environment. The source texts of the examples are primarily intended to provide a better explanation and visualization of the syntax and semantics of ABAP statements and not to solve concrete programming tasks. For production application programs, a dedicated solution should therefore always be worked out for each individual case. The example can use demo artifacts that are not released as APIs for use in ABAP for Cloud Development.

The following example shows a managed BDEF based on the CDS root view entity `DEMO_RAP_CHANGE_DOCS`.

- The root entity is defined as change documents master entity.

- The change document object `DEMO_CHGDOC` is used for logging changes.

- The child entity is defined as change documents dependent entity.

- The association `_parent` is defined in the entity behavior body of the child entity, thereby ensuring that changes in the child entity are logged in the change document object `DEMO_CHGDOC`.

- The logging options are defined in the entity behavior body.

**Note:** This example does not fully meet the requirements of the [RAP BO contract](../../abap-glossary/abenrap_bo_contract_glosry.md). It is intentionally kept short and simple and serves demonstration purposes only. For more information about the RAP BO contract, see the [Development guide for the ABAP RESTful Application Programming Model](https://help.sap.com/docs/ABAP_Cloud/f055b8bf582d4f34b91da667bc1fcce6/3a402c5cf6a74bc1a1de080b2a7c6978?version=sap_cross_product_abap).

``` abap
managed implementation in class bp_demo_rap_change_docs unique;
strict ( 2 );

define behavior for DEMO_RAP_CHANGE_DOCS alias Root
persistent table demo_dbtab_root
lock master
authorization master ( none )
changedocuments master ( DEMO_CHGDOC )
{

  changedocuments(create:key, update:data, delete:none);
  create;
  update;
  delete;
  field ( readonly:update ) key_field;
  association _child { create; }

  mapping for demo_dbtab_root corresponding
  {
  change_logging = char_field;
  }
}

define behavior for DEMO_RAP_CHANGE_DOC_CHILD alias Child
persistent table demo_dbtab_child
lock dependent by _parent
authorization dependent by _parent
changedocuments dependent by _parent
{
  changedocuments(delete:data, create:data);
  update;
  delete;
  field ( readonly:update ) key_field, key_field_child;
  association _parent;
}
```

The class `CL_DEMO_RAP_CHANGE_DOCS` demonstrates how the entries of the change document object can be evaluated using the class `CL_CHDO_READ_TOOLS`.

## Addition 1

`... asynchronous ...`

### Description

The optional addition `asynchronous` can be used when the response time of applications is significantly slowed down by writing large amounts of change document data. When this option is used, the data stored in the change document tables is still determined synchronously, but it is written to these tables asynchronously using the [background processing framework](../../abap-glossary/abenbackround_processing_fw_glosry.md). This can improve response times.

## Addition 2

`... utc ...`

### Description

Change document data has a time stamp, which is a field that indicates when the change document data was written. By default this time data is recorded in the current [system time zone](../../abap-glossary/abensystem_time_zone_glosry.md).

The optional addition `utc` can be used to explicitly specify that the time data for change documents is recorded in [UTC](../../abap-glossary/abenutc_glosry.md) format.
